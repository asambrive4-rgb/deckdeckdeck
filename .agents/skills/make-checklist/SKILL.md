# 체크리스트 문서화 스킬 (Make Checklist)

이 스킬은 현재 채팅 대화 중에 도출된 코드 분석·검토 결과(규칙 불일치, 중복 코드, 개선 제안 등)를 정형화된 체크리스트 마크다운 파일로 새로 작성(완전 덮어쓰기)하는 절차를 정의합니다.

---

## 🎯 핵심 원칙

1. **분석은 새로 하지 않고, 대화 내용만 체크리스트화**:
   - 이 스킬은 코드를 새로 조사하거나 추가 분석을 수행하지 않습니다.
   - 이미 사용자와의 대화(채팅 세션)에서 논의되고 도출된 분석 결과, 문제점, 파일 목록, 개선 방안만을 바탕으로 문서를 작성합니다.

2. **대상 파일 경로**:
   - 기본 대상 파일: `docs/체크리스트.md`
   - 사용자가 대화에서 다른 파일명(예: `docs/임시.md`, `docs/작업목록.md` 등)을 명시한 경우 해당 경로를 사용합니다.

3. **기존 파일 완전 새로 작성 (갈아엎기 / Overwrite)**:
   - 체크리스트 작성을 요청하면 기존 파일의 잔존 내용과 관계없이 **완전히 새로 갈아엎어서(Overwrite)** 작성합니다.
   - 단, 현재 채팅 세션 안에서 이미 '해결 완료'로 확인되거나 논의된 항목이 있다면 해당 항목은 체크(`- [x]`) 및 취소선(`~~...~~`)을 적용하여 작성합니다.

4. **완료 항목 취소선 규칙**:
   - 문서 상단에 항상 다음 규칙 문구를 명시합니다:
     ```markdown
     > 💡 **규칙**: 해결 완료된 항목은 체크박스를 체크(`- [x]`)하고, 항목명 및 본문 내용에 취소선(`~~...~~`)을 긋습니다.
     ```
   - 이미 해결된 항목은 표, 본문 제목, 본문 내용, 3부 로드맵 모두에 취소선(`~~...~~`)을 적용합니다.

5. **친절한 한국어 및 클릭 가능한 파일 링크**:
   - 비전공자도 이해하기 쉬운 명확하고 친절한 한국어로 기술합니다.
   - 언급되는 모든 소스 파일은 반드시 현재 프로젝트 작업 경로 기준의 클릭 가능한 마크다운 링크(`[파일명](file:///c:/경로/파일명.kt)`)로 작성합니다.

---

## 📋 표준 문서 구조 (템플릿)

문서는 반드시 아래의 4단계 구조로 작성합니다:

```markdown
# [제목: 코드베이스 검토 결과: 중복 및 규칙 불일치 체크리스트 등]

이 문서는 모듈 및 저장소 간에 **규칙이 서로 다르게 판단되고 있거나(버그 위험)**, **단순 중복되어 줄일 수 있는 코드**를 한눈에 파악하고 조치할 수 있도록 정리한 체크리스트입니다.

> 💡 **규칙**: 해결 완료된 항목은 체크박스를 체크(`- [x]`)하고, 항목명 및 본문 내용에 취소선(`~~...~~`)을 긋습니다.

---

## 📋 전체 요약 체크리스트

| 체크 | 구분 | 항목명 | 관련 위치/모듈 | 심각도 / 작업 성격 |
| :---: | :---: | :--- | :--- | :---: |
| - [ ] | **규칙 불일치** | [1. 항목 제목](#1-항목-앵커) | `모듈1` ↔ `모듈2` | ⚠️ 높음 (버그 위험) |
| - [x] | ~~**해결 완료**~~ | [~~2. 완료된 항목 제목~~](#2-완료된-항목-앵커) | ~~`모듈`~~ | ~~✅ 해결됨 (해결 근거)~~ |
| - [ ] | **코드 축소** | [3. 항목 제목](#3-항목-앵커) | `모듈` | ✂️ 파일 삭제 등 |

---

## 1부. ⚠️ 규칙/판단 기준 불일치 (버그 위험 요소)

### 1. [항목 제목]
- **관련 파일**:
  - 파일 역할 1: [`파일명.kt`](file:///경로)
  - 파일 역할 2: [`파일명.kt`](file:///경로)
- **어떤 문제인가요?**:
  - (비전공자도 이해할 수 있게 현상과 원인을 명확히 설명)
- **실제 영향**:
  - (이로 인해 어떤 오작동이나 불일치가 발생하는지 설명)
- **개선 방안**:
  - (어떻게 수정해야 일관성을 되찾는지 제시)

---

## 2부. ✂️ 중복 코드 및 단순화 가능 영역 (코드 다이어트)

### [번호]. [항목 제목]
- **관련 파일**:
  - [`파일명.kt`](file:///경로)
- **내용**:
  - (어떤 코드가 왜 중복되었는지 설명)
- **줄일 수 있는 효과**:
  - (제거 시 몇 줄이 줄어들고 어떤 이점이 있는지 설명)

---

## 3부. 권장 조치 로드맵

1. **Step 1 (최우선 - 버그 및 낭비 제거)**
   - [ ] 항목 1: ...
2. **Step 2 (안전한 코드 절감 및 단순화)**
   - [ ] 항목 ...
3. **Step 3 (구조적 리팩터링 및 공통화)**
   - [ ] 항목 ...
```

---

## 🛠️ 실행 절차

### 1단계: 채팅 세션 분석 내용 추출
1. 현재 대화에서 도출된 다음 항목들을 수집합니다:
   * 발견된 버그 및 규칙 불일치 목록
   * 중복 및 불필요한 코드 목록
   * 각 항목별 관련 파일 경로
   * 원인, 실제 영향, 개선 방안
   * 이미 해결 완료된 항목 여부 및 해결 커밋/근거

### 2단계: 최신 분석 내용 기반 마크다운 구성
1. 수집된 최신 대화 분석 내용만으로 표준 문서 구조(최상단 요약 표, 1부 규칙 불일치, 2부 코드 축소, 3부 로드맵)를 완전하게 작성합니다.
2. 현재 대화 중에 해결 완료로 확인된 항목은 체크박스(`- [x]`) 및 본문/제목/표/로드맵 전체에 취소선(`~~...~~`)을 적용합니다.
3. 모든 소스 파일 경로는 현재 프로젝트 기준의 클릭 가능한 마크다운 링크(`[파일명](file:///...)`)로 작성합니다.

### 3단계: 기존 파일 완전 덮어쓰기 (새로 작성)
1. 어차피 체크리스트 문서이므로 기존 파일의 잔존 내용과 관계없이 `write_to_file` 도구로 대상 파일(기본값 `docs/체크리스트.md`, `Overwrite: true`)을 완전히 새로 작성(갈아엎기)합니다.

### 4단계: 완료 보고
1. 체크리스트 문서가 어느 경로에 생성/갱신되었는지 보고합니다.
2. 반영된 전체 항목 수와 완료/미완료 항목 현황을 짧게 요약합니다.
3. 사용자가 다음으로 진행할 작업을 선택할 수 있도록 안내합니다.
